# 0.2.2 — two copy formats: full map and readable params

## review of 0.2.1

The scene link always carried everything, so two links with the same 36 sites but
different synth settings each shipped ~1.6 kB of base64. `snapshot()` and
`restoreScene()` also repeated the mode/steep/N mapping field by field, which made
a second format a copy-paste risk. The readable table now feeds both formats, and
both restore paths go through one `applyParams()`. There was also no way to read a
link without a browser, so `experiments/decode-link.js` was added for that.

## changes

- `Settings` gained an ordered `PARAMS` table: `freq`, `freq-steep`, `vol`,
  `vol-steep`, `env`, `env-steep`, `n`, with GUI labels (`point`/`dist`,
  `dist`/`const`, `off`/`dist`). `formatParams`, `parseParams`, `toParamsUrl`,
  `paramsFromUrl`, and `paramsFromScene` are exported. Parsing accepts any
  non-empty subset of known keys, rejects unknown keys and out-of-range values,
  and needs no base64 or percent escapes.
- Params are the visible HUD controls only. Points, masses, tones, probe, viewport,
  and pause/mute stay in the map link; a params link never changes transport state
  and never rebuilds the field.
- HUD: `copy map URL` (was `copy settings URL`) and `copy params` share one
  clipboard/fallback helper. Status reads `map link copied` / `params link copied`.
- `loadUrl()` restores a scene when `#scene=` is present, otherwise applies params
  on top of the live field. A fresh page with a params hash fills `n` points.
- `experiments/decode-link.js` (`npm run decode -- '<link>'`) prints any scene or
  params link as GUI values.

## validation

- `npm test` green: voronoi, physics, tones, smoke, and feature checks, including
  the new params checks (readable link without `scene=` or base64, fresh-page fill,
  apply-on-live-field without touching sites or transport, omitted keys preserved,
  strict parsing, clipboard fallback).
- Decoded both supplied debug links with `experiments/decode-link.js`. Both are
  2048 x 923 with 36 points, running and unmuted, `n = 36`; the first is
  `freq = point id, steep 15`, `vol = distance, steep 39`, `env = distance, steep 77`;
  the second is `freq = distance, steep 54`, `vol = distance, steep 53`,
  `env = distance, steep 6`.
- Replayed the same links through the stub page: 36 points restored, radio/slider
  values match, and `copy params` produced
  `#freq=point&freq-steep=15&vol=dist&vol-steep=39&env=dist&env-steep=77&n=36`
  and
  `#freq=dist&freq-steep=54&vol=dist&vol-steep=53&env=dist&env-steep=6&n=36`.
- `file://` params hash applied to a 36-point field without changing the field or
  the paused state.
